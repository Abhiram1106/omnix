# Workflow: Error Intelligence

Turn each fixed bug into prevention knowledge. Match new errors against past ones.

## Activation

- User pastes an error or stack trace.
- A test failure or build break is observed.
- `omnix error <text>` CLI call (FUTURE).

## Procedure for matching against past errors

```
1. Normalize the error:
   - Strip file paths, line numbers, timestamps, request IDs.
   - Keep: error message, stack frame method names, library names.

2. Search 03-ERRORS/error-memory.md for entries with:
   - Same library/framework
   - Similar error message (substring match or known synonyms)
   - Same area (auth, db, frontend, etc.)

3. If match found:
   - Show user the past entry: Date, Root Cause, Fix, Prevention Rule.
   - Ask: "Same root cause? Apply same fix?"

4. If no match:
   - Proceed with new investigation.
   - On fix: write a new error-memory entry.
```

## Error memory entry contract

Every fixed error MUST produce an entry with these fields (from `templates/error-entry.md`):

```
- Date
- Project
- Area              ← critical for filtering
- Symptom           ← what the user saw
- Root Cause        ← what was actually wrong
- Fix               ← what changed (file:line if specific)
- Prevention Rule   ← the rule that, if followed, would have prevented this
- Do Not Repeat     ← short one-liner for anti-patterns.md
- Regression Test Added  ← yes / no + path
- Related Files     ← paths involved
- Related Session Digest ← link to session that fixed it
```

Without **Prevention Rule** the entry has no future value. Reject entries that skip it.

## Anti-patterns promotion

When 3 or more entries share the same `Prevention Rule`, promote it to `anti-patterns.md`:

```
## Anti-pattern: <rule>
Seen in: 3+ incidents (dates).
Reason: <why it keeps happening>.
Detection: <how to catch in review>.
```

## INDEX.md format

`03-ERRORS/INDEX.md` is generated by `omnix sync-memory --index`:

```markdown
# Error Index
<!-- One line per entry. Used for fast retrieval. -->

- 2026-05-10 | auth | JWT refresh loops on expired token | Fixed: src/auth.ts:42 | Rule: always check expiry before refresh
- 2026-04-22 | db | N+1 query in user list | Fixed: src/repo/users.ts | Rule: eager-load relations in list queries
```

The AI loads INDEX.md first, then loads full entries only for matching rows.

## Failure modes
- **No INDEX.md** → fall back to scanning full error-memory.md (slower).
- **Entry without Prevention Rule** → flag, refuse to add to INDEX.
- **False positive match** → user disagrees, marks as different; algorithm learns nothing yet (TODO).
