## Context Engineering

### CE-01: Progressive Disclosure Retrieval
**Source:** Agent-Skills-for-Context-Engineering / `context-fundamentals/SKILL.md`  
**Why it matters:** Current Omnix retrieval dumps files into context. Progressive disclosure loads names first, summaries on match, full content only for top-N — dramatically reducing wasted tokens.  
**Integration:** Fully integrate into `retrieve-context.ts`. Replace current keyword frequency with 3-tier loader.  
**Approach:** Redesign  
**Risks:** Requires summary generation pass — adds vault-init overhead  
**Token/context impact:** Reduces average retrieval context by ~60%  
**Implementation:**
```typescript
// Tier 1: always load — file index (names + 1-line descriptions)
// Tier 2: load on match — file summaries (first 3 lines)
// Tier 3: load on selection — full content (top-N by relevance)
```
**Priority:** P0 | Value: 10/10 | Difficulty: Medium | Maintenance: Low

### CE-02: Position-Aware Context Placement
**Source:** Agent-Skills-for-Context-Engineering  
**Why it matters:** Critical info at start + end of context gets 85–95% recall. Middle gets 76–82%. Current AGENTS.md dumps everything in order without awareness.  
**Integration:** Update AGENTS.md template structure. Critical rules at top, memory loop at top, supplementary info in middle.  
**Approach:** Partially integrate — apply to all adapter templates  
**Token/context impact:** ~15% improvement in rule recall without any token cost change  
**Priority:** P1 | Value: 8/10 | Difficulty: Low | Maintenance: Low

### CE-03: Task-Type-Aware Retrieval Modes
**Source:** Agent-Skills-for-Context-Engineering + existing Omnix retrieval modes  
**Why it matters:** A debugging session needs error memory first. A feature build needs architecture first. One retrieval order doesn't work for all tasks.  
**Integration:** Wire existing retrieval modes (minimal/balanced/deep/architecture/debugging) to specific file priority lists in `retrieve-context.ts`. Currently modes exist but file priorities aren't differentiated.  
**Approach:** Fully integrate  
**Priority:** P0 | Value: 9/10 | Difficulty: Medium | Maintenance: Low

### CE-04: Observation Masking
**Source:** Agent-Skills-for-Context-Engineering  
**Why it matters:** Tool outputs dominate agent token budgets (83.9% in trajectories). Omnix session digests include all command outputs verbatim. Summarize tool outputs immediately after processing; keep only recent/critical.  
**Integration:** Add summarization pass in `write-digest.ts` — compress `commandsRun` outputs to 1-line summaries. Add `compressedAt` timestamp to old digest entries.  
**Approach:** Partially integrate  
**Priority:** P1 | Value: 7/10 | Difficulty: Medium | Maintenance: Low

## Memory Systems

### MS-01: Vault Lifecycle Management (hot/warm/cold/archive)
**Source:** Agent-Skills-for-Context-Engineering `memory-systems/SKILL.md`  
**Why it matters:** Without lifecycle, vault becomes noise after 30 sessions. Retrieval degrades. Gap G-04.  
**Integration:** Add `VaultLifecycle` system to `sync-memory.ts`. Auto-compress warm → cold at 30 days. Archive cold → archive at 90 days. Keep lightweight index of archived entries.  
**Approach:** Fully integrate  
**Risks:** Compression must not lose important decisions/errors — summaries must be accurate  
**Priority:** P0 | Value: 10/10 | Difficulty: Medium | Maintenance: Low

### MS-02: Memory Bank Pattern (lightweight identifiers)
**Source:** Agent-Skills-for-Context-Engineering  
**Why it matters:** Instead of loading full session digests, keep a lightweight index (date, tool, files-changed count, one-line summary) always in context. Load full digest only when needed.  
**Integration:** Add `vault-index.md` to `02-PROJECTS/` — auto-generated by `sync-memory`. One line per session with key metadata.  
**Approach:** Fully integrate  
**Priority:** P1 | Value: 9/10 | Difficulty: Low | Maintenance: Low

### MS-03: Staleness Detection
**Source:** Gap analysis G-05  
**Why it matters:** Stale vault entries silently override correct code state.  
**Integration:** Add `last-verified` + `status: active|stale|superseded` to all vault templates. Add staleness warning in `sync-memory --stats`.  
**Approach:** Fully integrate  
**Priority:** P1 | Value: 8/10 | Difficulty: Low | Maintenance: Low

### MS-04: Error Intelligence (match new errors against past fixes)
**Source:** gstack `/investigate` pattern + Gap G-08  
**Why it matters:** Error memory is write-only. Users encounter same errors repeatedly.  
**Integration:** Add `omnix error-match <error-text>` command. BM25-style term frequency matching against error-memory.md. Returns top-3 matches with fixes.  
**Approach:** Fully integrate  
**Priority:** P1 | Value: 9/10 | Difficulty: Medium | Maintenance: Low

## Token Optimization

### TO-01: Token Budget Enforcement in Retrieval
**Source:** Agent-Skills-for-Context-Engineering + prompt-master  
**Why it matters:** No budget enforcement means context window can be silently exhausted. Gap G-02.  
**Integration:** Add token budget to `retrieve-context.ts`. Estimate tokens per file (chars/4 heuristic). Stop selecting files when budget is hit. Warn user.  
**Approach:** Fully integrate  
**Budgets:** minimal: 500 tokens, balanced: 1500, deep: 3000, architecture: 4000, debugging: 2000  
**Priority:** P0 | Value: 9/10 | Difficulty: Low | Maintenance: Low

### TO-02: Vault Size Monitoring + Auto-Warning
**Source:** Gap G-02 + G-04  
**Why it matters:** No visibility into vault growth rate.  
**Integration:** Extend `omnix sync-memory --stats` with: total tokens (estimated), growth rate (files/week), warning at 100+ files.  
**Priority:** P1 | Value: 7/10 | Difficulty: Low | Maintenance: Low

### TO-03: "Every Word Must Change Output" Audit Principle
**Source:** prompt-master  
**Why it matters:** AGENTS.md and adapter templates contain bloated explanations. Strip anything that doesn't change AI behavior.  
**Integration:** Apply as a content audit pass to all adapter templates. Remove boilerplate explanations. Keep only actionable rules.  
**Approach:** Reference only — apply as editorial discipline, not code  
**Priority:** P1 | Value: 7/10 | Difficulty: Low | Maintenance: Low

## Workflow Orchestration

### WO-01: Atomic Skill Design Principle
**Source:** gstack  
**Why it matters:** Current Omnix workflows are long documents covering multiple concerns. Atomic skills (one purpose, clear I/O) are more composable and reliable.  
**Integration:** Apply as design principle to all new skills. Existing workflows remain as guides. New skills follow: single purpose, explicit input, explicit output, max 500 tokens.

### WO-02: Safety Command Layer
**Source:** gstack (`/careful`, `/freeze`, `/guard`)  
**Why it matters:** No safety layer in Omnix. Before destructive operations, AI should confirm. Before migrations, AI should freeze state.  
**Integration:** Add to AGENTS.md: mandatory confirmation before: `rm`, `drop table`, `force push`, `reset --hard`, migration runs. Add `omnix freeze` command that tags git state before risky ops.  
**Approach:** Partially integrate — confirmation rules in AGENTS.md, `omnix freeze` as a thin git tag wrapper  
**Priority:** P1 | Value: 9/10 | Difficulty: Low | Maintenance: Low

### WO-03: Progress Checkpoint + WIP Commit Pattern
**Source:** gstack  
**Why it matters:** Long AI sessions (30+ minutes) lose context. WIP commits with structured metadata enable session recovery.  
**Integration:** Add WIP commit template to session-digest workflow. When session ends, AI optionally creates: `git add -A && git commit -m "wip: [task] -- context: [summary]"`.  
**Priority:** P2 | Value: 7/10 | Difficulty: Low | Maintenance: Low

### SD-01: Minimal Digest Mode (3 fields from git diff)
**Source:** Gap G-03  
**Why it matters:** 17-field digest causes fatigue and abandonment.  
**Integration:** `--auto` already does git diff. Add `--minimal` that produces 3 fields only: changed-files, fixed-errors, next-step. Make minimal the default for sessions where git diff < 5 files.

### SD-02: Digest Quality Scoring
**Source:** everything-claude-code continuous learning pattern

**Integration:** Add quality heuristics: score = (fields_filled / total_fields) × (decisions_count + errors_count). Flag low-quality digests in `sync-memory --stats`.
