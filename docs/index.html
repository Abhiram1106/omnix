How it works

What Omnix actually does — precisely.

Omnix is not a runtime. It does not run autonomously, call AI APIs, or execute code on your behalf. It is a CLI that writes structured files into your project. Your AI tool reads those files.

One-sentence summary: Omnix writes files → your AI tool reads them → your AI tool behaves better.

The three things Omnix does

1

Creates the memory vault

Runs omnix init → creates .obsidian-ai-memory/ in your project with 11 folders. These are plain markdown files. Your AI tool reads them. You can also open the folder in Obsidian for graph view — or never open Obsidian, it's just files.

Sessions folder accumulates a digest after every meaningful session. Error memory stores every fixed bug with root cause + fix + prevention rule. Decisions folder stores ADRs. Architecture folder stores system overview and threat models.

omnix init --yes
2

Installs adapter files for your AI tool

Each AI tool reads a different file for project instructions. Claude Code reads CLAUDE.md. Cursor reads .cursor/rules/*.mdc. Omnix generates the right file for each tool, pointing it at the memory vault and AGENTS.md.

AGENTS.md is the source of truth — it contains the memory loop instructions, safety rules, agent routing table, and skill discovery table. All tool-specific adapter files are thin wrappers that import AGENTS.md.

omnix install-adapters --adapters claude,cursor,generic
3

Provides 10 live skill engines + 22 CLI commands

Skills are not just instruction files. 10 of them have real runtime handlers — they analyse your actual project (code files, package.json, git history) and produce output: test gap reports, security scans, debugging hypotheses, release checklists.

The CLI also provides: error memory search (BM25), vault health scoring, session diff tracking, git hook installation, vault schema validation, and activity heatmaps.

omnix skills --run security-threat-modeler

What happens when you open Claude Code after init

Claude Code reads CLAUDE.md on every session. Your CLAUDE.md has:

  • @AGENTS.md import — loads the full memory loop, routing table, and skill table
  • Memory loop instructions — retrieve context before starting, write digest after finishing
  • Safety rules — confirm before destructive operations, never expose secrets
  • Active skills section — any skills you activated with omnix skills activate <name>

Claude Code doesn't "know" Omnix. It just reads the file. The file tells it how to behave. This is convention, not magic.

Important limitation: Whether your AI tool actually follows the instructions in CLAUDE.md depends on the tool and model. Claude Code with Sonnet/Opus has the best compliance. Other tools vary. Omnix cannot force any AI tool to do anything — it can only write clear instructions.

Tutorial

5-step walkthrough — start here.

Run omnix tutorial for the interactive CLI version. Or read the full walkthrough here — this is more detailed than the CLI output.

Prerequisite: Run npx create-omnix first. Then come back here.
1
Understand what Omnix installed
2 min
▶

Run this to see everything Omnix installed and your current health score:

omnix detect    # list every installed file
omnix status    # health score + what needs setup
omnix verify    # confirm files are AI-readable

What you'll see in status:

  • Health score 0–100 — starts around 70/100 after init
  • Vault present — the 11-folder memory vault
  • Installed adapters — which AI tools got config files
  • project-context.md customized — starts as "needs setup" until you run omnix scan --write
  • Next steps — the tool tells you exactly what to do next
The score will be ~70/100 after a fresh init. That's normal. Run omnix scan --write in step 2 to improve it.
2
Populate your project context
1 min
▶

Right after init, .obsidian-ai-memory/02-PROJECTS/project-context.md has placeholder content. Omnix can auto-detect your stack and fill it in: 

omnix scan --write

This detects your:

  • Languages — TypeScript, Python, Go, Rust, etc.
  • Frameworks — Next.js, Express, FastAPI, Django, etc.
  • Package manager — npm, pnpm, yarn, pip, cargo
  • AI tools installed — what adapter files exist
  • Testing frameworks — Vitest, Jest, pytest, etc.

Then writes it all to 02-PROJECTS/project-context.md and 02-PROJECTS/current-state.md.

After this, run omnix status again — you'll see the score jump because project-context.md is now populated.

Optional: Add deeper context manually — your team, deadlines, constraints, tech debt. The AI will use everything in this file.
3
Learn the memory loop
3 min — most important step
▶

The entire value of Omnix depends on one habit: Retrieve → Work → Digest.

🔍 Retrieve

Load relevant vault context before starting any task

→

⚙️ Work

Do the actual task with your AI tool

→

📝 Digest

Record what happened in the vault

RETRIEVE — before starting any task

omnix retrieve-context --task "fix login bug"
# Loads: error-memory first (debugging mode auto-detected)
# Then: project-context, recent sessions
# Respects token budget — no vault dumping

This prints a context block you paste into your AI tool, or put in your CLAUDE.md. The retrieval mode is auto-detected: "fix login bug" → debugging mode (loads error memory first). "add OAuth feature" → deep mode (loads project context + architecture).

DIGEST — after meaningful work

omnix session-digest --auto --tool claude-code
# auto = reads git diff to detect what changed
# writes to .obsidian-ai-memory/01-SESSIONS/YYYY-MM-DD/

Or install a git hook to do this automatically after every commit:

omnix hooks --install post-commit
# From now on: auto-writes digest after every git commit

AFTER FIXING A BUG — record it

omnix skills --run error-intelligence --input \
  "TypeError: null | user.createdAt was undefined | added null guard | always check optional fields"
# Writes to 03-ERRORS/error-memory.md
# Next time you hit a similar error, omnix error-match finds it

Why this matters: After 10 sessions, your error memory has 10 entries. After 30 sessions, your AI tool stops making the same mistakes because it searches past fixes first. That's the compounding value.

4
Run your first live skill
5 min
▶

Skills are the most powerful part of Omnix. 10 skills have live runtime handlers that actually analyse your code:

# See all skills
omnix skills

# Scan your repo for code issues
omnix skills --run repo-scanner
# → entry points, hotspots, test gaps, 0–100 risk score
# → writes to 05-ARCHITECTURE/repo-scan.md

# Security scan (STRIDE + OWASP patterns)
omnix skills --run security-threat-modeler
# → scans source for eval, innerHTML, SQL concat, weak crypto
# → checks .env is gitignored, no hardcoded keys
# → writes to 05-ARCHITECTURE/threat-model.md

# Debug an error
omnix skills --run debugging-specialist --input "TypeError: cannot read property of null"
# → searches your error memory first
# → classifies error type
# → generates hypothesis + 4-phase plan

# Test gap analysis
omnix skills --run test-architect
# → counts existing tests
# → finds src files with no test
# → prioritised gap list (auth, payment = highest priority)

Activate a skill in Claude Code — so Claude loads it automatically:

omnix skills activate debugging-specialist
# Adds @import to CLAUDE.md Active Skills section
# Claude Code now loads the skill on every session
5
Install git hooks + check secrets
2 min
▶

Two git hooks make Omnix work passively — no manual steps needed after coding sessions:

omnix hooks --install all
# pre-commit:  blocks commit if secrets detected in vault
# post-commit: auto-writes session digest after every commit

What the pre-commit hook checks:

  • OpenAI / Anthropic keys (sk-...)
  • GitHub tokens (ghp_...)
  • AWS access keys (AKIA...)
  • JWT tokens (three base64 segments)
  • Database connection strings with passwords
  • PEM private keys
  • .env secret value patterns

Run anytime manually:

omnix check-secrets           # scan vault now
omnix check-secrets --json    # machine-readable (for CI)

You're done. From here, the vault builds up passively via git hooks. Check in occasionally:

omnix status          # health score + what to improve
omnix vault streak    # activity heatmap + streak stats
omnix diff            # changes since last session digest
The compound effect: After 2 weeks of using Omnix with git hooks, your vault has 14+ session digests, your error memory has real entries, and your AI tool starts every session with actual project context. That's when the value becomes obvious.
Memory System

The memory vault.

Plain markdown files in your project. Your AI tool reads them. Obsidian can visualize them.

.obsidian-ai-memory/
  00-INBOX/ ← quick captures, unsorted notes
  01-SESSIONS/ ← one folder per day, one digest per session
    2025-01-15/
      session-1430-claude-code.md
  02-PROJECTS/ ← project context, active goals, current state
    project-context.md ← auto-populated by omnix scan --write
    active-goals.md
  03-ERRORS/ ← BM25-searchable error memory ⭐
    error-memory.md ← root cause + fix + prevention per bug
    anti-patterns.md ← promoted from recurring errors
  04-DECISIONS/ ← ADR index, decision entries
  05-ARCHITECTURE/ ← system overview, threat model, repo scan
  06-WORKFLOWS/ ← active + completed workflows
  07-LESSONS/ ← lessons learned, external research cache
  08-PROMPTS/ ← effective prompts, failed prompts
  09-AGENTS/ ← AI tool / model behavior notes
  10-DAILY-DIGESTS/ ← daily summaries, session archives
  templates/ ← fill-in templates for each record type

Secret protection

Every session digest is sanitized before writing. These patterns are redacted:

  • OpenAI/Anthropic keys (sk-...), Stripe keys, GitHub tokens
  • AWS access key IDs (AKIA...), Slack tokens
  • JWTs (three base64url segments)
  • PEM private key blocks
  • Database connection strings with passwords
  • .env lines matching *_KEY=, *_SECRET=, etc.

Additionally, .omnix/memory/ and .omnix/cache/ are auto-added to .gitignore.

FAQ

Common questions.

Does Omnix require Obsidian?

No. The vault is plain markdown files. Obsidian is optional — it adds graph view and backlinks if you want them.

Does Omnix call any AI API?

No. Omnix is a local CLI. No network calls except omnix research which queries npm/GitHub/Node.js registries (with vault caching).

Will it work with my AI tool?

It will work with any tool that reads project rule files. Claude Code and Cursor have the best compliance. The effect with other tools depends entirely on whether the tool loads and follows the rule files.

The Windsurf/Cline/Roo adapter isn't loading.

These are TEMPLATE adapters. Their file paths change frequently. Check each tool's current documentation for the correct rules file location, then compare it with what Omnix installed.

My health score is 70 after init. Is that bad?

No, that's normal. Run omnix scan --write to populate project-context.md. That alone takes it to ~85. The score improves naturally as you use the tool.

Can I add my own skills?

Yes. Create a SKILL.md with required frontmatter in .omnix/skills/<name>/. It will appear in omnix skills automatically. See packages/skills/debugging-specialist/SKILL.md for the format.

Will Omnix commit secrets to my vault?

Session digests are sanitized before writing. .omnix/memory/ is auto-added to .gitignore. The pre-commit hook blocks accidental secret commits. That said: never commit your vault to a public repo — treat it like .env.

How do the reference repos (Agent-Skills, gstack, etc.) relate?

They were pattern sources used during development — patterns were extracted and are now baked into Omnix's skill system and architecture. Those repos are no longer needed and have been removed from the workspace.
